# Domain docs

This repository uses a single-context layout. Before exploring, read the root `GLOSSARY.md` and the relevant ADRs in `docs/adr/`. If either is missing, proceed silently. `/domain-modeling` creates these documents when terms or decisions are settled.

Use glossary terms in issues, proposals, hypotheses, and test names. If a term is missing, check whether the project already uses another term. If it is a real gap, note it for `/domain-modeling`.

If a recommendation conflicts with an ADR, name the ADR and explain why the decision is worth reopening.
